# Authenticator Desktop (Python)

这是基于原浏览器验证器功能重写的 Windows 桌面版。源码、构建文件和发布产物都在本目录，不会修改原浏览器扩展。

## 成品位置

构建完成后的程序位于：

`release\AuthenticatorDesktop.exe`

双击该文件即可运行，无需安装 Python。

## 已实现功能

- 本地 TOTP、HOTP、Steam Guard 和 Battle.net 动态验证码
- 与验证码同级的本地密码本：支持独立搜索、分组、置顶、复制、显示/隐藏和打开网站
- 参考仪表盘式完整界面：单行顶部应用栏、验证码/密码本双色分段滑块、混合导航侧栏、四项数据概览、共享 Canvas 数据表和底部操作栏
- 窗口小于 `1120px` 时自动切换为紧凑工具栏和图标侧栏，放大后恢复完整导航与操作文字
- 侧栏可按全部、置顶、自定义分组、常用服务商和其他服务筛选，并与当前模块搜索条件叠加
- 密码记录的名称/服务为选填，用户名与密码为必填；空名称在列表中自动使用用户名
- 内置安全密码生成器，长度可选 8～128，并可配置大小写、数字、符号和易混淆字符
- 新增、编辑、删除、置顶和复制验证码
- 新增账号支持“扫码识别”：点击密钥栏旁的扫码按钮后先自动识别屏幕，未找到时直接进入框选；普通二维码自动回填账号，Google 导出二维码批量导入其中的账号
- 新增账号时服务商可手动输入或从已有服务商下拉选择，并默认沿用上一次使用的服务商
- 500+ 账号的即时搜索：输入账号或服务名称后立即筛选，无需按回车；列表会显示当前匹配数量
- 默认中文界面，紧凑的多列账号列表同时展示服务、账号、验证码、剩余时间、验证码类型和创建时间
- 超长账号会稳定显示省略号且不会侵入验证码列；倒计时圆环采用 8 倍矢量路径采样、圆头笔画和行背景预合成
- 清新浅色的毛玻璃视觉：雾蓝背景、玻璃表面、柔和边界和明确的操作状态
- 新建与导入账号会记录创建时间；未置顶账号默认按创建时间从新到旧排序，旧版数据会标记为“历史数据”
- 分组管理：可新建、重命名和删除自定义分组；所有账号始终属于“默认分组”，也可同时加入多个自定义分组
- 当前分组下新建账号会自动加入该分组；在账号列表中可通过 Ctrl/Shift 多选后批量调整分组归属
- 默认窗口为 `960x640`，支持自由调整，关闭程序后会记住正常窗口大小
- 轻量悬浮窗模式：仅显示新增入口和最近两个账号；扫码新增会先自动识别屏幕，未找到时无提示进入框选，成功账号高亮 5 秒
- 窗口置顶开关，可在工具栏中切换并自动记住；保险库锁定/解锁合并为一个状态按钮
- `otpauth://` URI、Google Authenticator 迁移二维码导入与标准 URI 导出
- 可直接生成 Google Authenticator 批量迁移二维码；账号较多时自动分页，使用手机逐张扫描即可导入
- 桌面版备份支持加密 `.authbak` 与可直接阅读的明文 JSON 两种导出，并可自动识别导入
- 导入原扩展的未加密 JSON 账号备份
- 本地敏感数据强制使用 AES-256-GCM 加密，Windows DPAPI 支持正常启动自动解锁
- 轻量的本机 HTTP API：支持账号新增和按账号读取密钥，仅监听 `127.0.0.1`

账号、密码本和设置数据保存在 EXE 同级的 `data` 文件夹中。首次启动时程序会
自动创建该文件夹并要求设置至少 8 个字符的主密码；以后正常启动由当前 Windows
用户的 DPAPI 凭据自动解锁。移动程序时应将 EXE 与 `data` 文件夹一起移动；换电脑
或更换 Windows 用户后需输入主密码重新绑定。请妥善保管主密码。

## 密码本

完整界面顶部可在“验证码 / 密码本”之间切换。两边分别保留搜索条件、当前分组和列表选择；轻量悬浮窗仍只显示验证码。密码本默认按“置顶优先、创建时间从新到旧”排列，密码列固定显示 12 个圆点，只有单选记录后才能临时显示明文。

密码本拥有独立默认分组和自定义分组，不与验证码分组混用。备份会同时包含验证码、密码记录及两套分组，但不会包含 API 令牌、常驻剪贴板或设备设置。加密备份在同一 Windows 用户下可无感导入，跨机时使用生成备份时的主密码恢复；明文 JSON 会直接暴露密钥和密码。密码记录不会通过本机 API 暴露。

原扩展的加密备份使用不同的浏览器/Argon2/CryptoJS 格式，不能直接导入。请先在原扩展中解锁并导出未加密 JSON，或导出 `otpauth://` URI，再导入桌面版。

## 轻量悬浮窗

在完整界面顶部点击“轻量模式”进入。悬浮窗可通过“置顶”按钮切换是否始终置顶，按钮会用平面或高亮凸起状态表示当前状态。悬浮窗只保留搜索、扫码新增、手动添加、最近两个账号及验证码查看功能。搜索框与完整界面共用筛选条件，输入后会即时更新最近账号。验证码倒计时只更新文本，不会重建账号区域。

点击账号邮箱可直接复制账号，点击验证码可直接复制验证码。“最近添加”右侧的常驻剪贴板支持单击复制、双击编辑，内容会保存到设置文件并在下次启动时恢复。“扫码新增”是默认操作：点击后程序先自动识别整个屏幕，未找到有效二维码时会直接进入区域框选，不弹出中间提示；识别成功后直接写入保险库，并将新增账号边框高亮 5 秒。新增按钮右侧的下拉菜单可以改为“手动添加”；点击“完整界面”即可恢复主窗口。

## 分组

左侧导航可在“全部账号”、“已置顶”、自定义分组和服务商范围间切换。点击列表上方的“新建分组”可立即创建并切换到新分组；“管理分组”中可重命名或删除自定义分组。删除分组不会删除其中账号，账号会继续保留在默认分组及其余分组中。

账号列表支持单击、Ctrl+单击和 Shift+单击/Shift+上下键范围多选。选择一个或多个账号后，点击“分组”可批量勾选或取消勾选自定义分组；默认分组是系统分组，始终保留。

## 本机 API

程序运行后会启动一个仅限本机访问的 HTTP 服务：`http://127.0.0.1:8765/v1`。服务地址和随机访问令牌可在顶部“更多 -> 设置”中复制。所有请求必须带以下请求头：

```text
X-Authenticator-Token: <设置页中的访问令牌>
```

保险库锁定时，API 不会返回账号或密钥。API 不提供任何密码本端点。请只把令牌交给受信任的本机程序。

列出账号元数据（不包含密钥）：

```http
GET /v1/accounts
```

列出分组及各分组包含的账号数量：

```http
GET /v1/groups
```

账号 API 响应中的 `group_ids` 是账号所属的分组 ID；`groups` 同时提供 ID 与名称，方便显示。

按账号 ID 读取密钥：

```http
GET /v1/accounts/{id}/secret
```

也可以按服务商和账号名称读取；匹配多个账号时 API 会返回 `409`，以免误取密钥：

```http
GET /v1/accounts/secret?issuer=GitHub&account=alice@example.com
```

新增账号：

```http
POST /v1/accounts
Content-Type: application/json

{
  "issuer": "GitHub",
  "account": "alice@example.com",
  "secret": "JBSWY3DPEHPK3PXP",
  "otp_type": "totp",
  "secret_encoding": "base32",
  "period": 30,
  "digits": 6,
  "algorithm": "SHA1",
  "pinned": false,
  "group_ids": ["default"]
}
```

`otp_type` 可选值为 `totp`、`hotp`、`steam`、`battle`；未填写的字段使用桌面程序默认值。`group_ids` 为可选的已存在分组 ID 列表；省略时账号自动加入 `default`（默认分组），未知 ID 会返回 `400`。API 仅使用 Python 标准库，不增加运行时第三方依赖。

## 重新构建

当前环境已包含 Python 和 PyInstaller。双击 `build.bat`，或在本目录运行：

```powershell
python build_exe.py
```

构建脚本会依次执行 pytest、ruff、mypy、源码编译、PyInstaller 打包、打包后内置自检和 EXE 启动冒烟，并输出版本号、文件大小与构建耗时。内置自检覆盖 RFC HOTP/TOTP 向量、密码生成器、二维码依赖、URI 导入、验证码与密码记录的加密保险库往返、设置和 API 路由。

开发检查依赖可通过 `pip install -r requirements-dev.txt` 安装；测试位于 `tests/`。`python scripts/capture_ui_snapshots.py` 会使用隔离的临时保险库生成三个分辨率下的两个模块截图，用于 UI 回归检查。领域规则、事务写操作、持久化、API、扫码和 UI 控制器已经分别迁移到 `domain/`、`application/`、`infrastructure/` 与 `presentation/`。
